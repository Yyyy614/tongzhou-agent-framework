# 0.6 隔离开发与验收

基线：486b276。遵循 FRAMEWORK_DESIGN 1.1，保留现有身份、精确挂载、记忆、任务和 A1/A2；业务逻辑继续留在外部能力包。公司私有市场内容不进入公开源码仓库。

## 依赖与进度

- [x] P1：版本化资源、成果引用、资源 ACL、授权索引与可重验的 ContextPack。
- [x] P2：结构化工作回传；控制事实由宿主生成，全文作为可授权的成果引用。
- [x] P3：员工提交 Skill/插件候选、无执行检查、审核发布、定向安装与撤回；复用精确挂载。
- [x] P4：来源统一配置、持久事件、观察模式、工作归属候选与 Thread 订阅；连接现有工作和停止机制。
- [x] P5：实际模型输入接入 ContextPack，原生公司 Harness 和管理后台接入市场、资源、审核与事件去向。
- [x] P6：隔离服务器、原生工作流、独立能力包和回归验收；记录真实模型与模拟外部平台的证据界限。

P1/P2 是 P3/P4/P5 的共同基础。验收时使用独立工作树、全新回环数据库、独立员工/设备和本机端口；不迁移或清空旧记录，不部署线上。

## 最小完整流程

1. 员工提交包；上传阶段不运行入口、依赖安装或 Skill 脚本。维护人审核不可变版本，发布到个人/部门/公司范围。
2. 员工在公司 Harness 选择自己的岗位安装已发布且获准的能力。发布、挂载、工具与数据授权分别检查，凭证只引用受管连接。
3. 模型先获得有界能力/资源索引；展开正文时重新鉴权。不同工作不会携带另一工作的完整聊天历史。
4. 管理员配置一次来源、人员映射和职责。员工登录即可接收工作，不逐人配置 Bot。
5. 来源事件先持久接收、去重。已有有效订阅直达原工作；新事件按确定规则或受限语义候选归属；不明确则待处理，不编造成功。
6. 重复事件不重复执行；观察模式不派工；停止/撤权后不执行新动作；未知回执不自动重放。
7. 工作进展以状态、回执、成果版本和未决问题展示；完整资料按权限展开，管理摘要不采用全文前缀冒充必要事实。

## 已落实的评价与边界

- 资源目录按域和当前 ACL 检索；正文分页加载。版本和摘要的来源不会替代授权。资源 ACL 变更有递增代次，撤回再恢复也不能复活旧 ContextPack。
- 网关真正构造模型输入：当前回合输入、宿主指令、有限目录、选定资料、本人 INDEX，以及本回合收到的模型响应/公司工具回执。客户端旧 system、聊天历史和伪造 tool_result 不进入模型上下文。新回合不隐式带旧聊天；要继续协作工作走显式轮次或选择资料引用。
- ContextPack 在模型发送和 MCP 动作前重验。已经准入的外部动作仍需收尾/核实，不能宣称撤回会撤销已经提交的操作。
- 新结果使用 `references-v1` 标识。状态由宿主记录，Agent 报告带来源和受众过滤；完整回复是本人私有资源。结果登记失败返回待核实，不能走旧记录前缀兼容分支。真正旧记录保持原有读取规则。
- 语义归属只接收事件摘要与管理员允许的岗位候选，无工具/私有记忆；独立记录公司模型渠道用量。不能确定就进入人工确认，不当作已完成工作。
- 公司事件来源可订阅新插件事件及 `work.task_failed`。原有提醒/审批/个人绑定保持兼容；自动辅助工作不会无限触发自己的失败辅助链。
- 受管钉钉/飞书/企微普通消息共享统一映射与订阅；原生工作中心负责明确的停止、恢复、核实。三平台真实授权与网络收发须用正式测试应用另验，模拟适配器不能代替这一证据。
- 原生构建新增 `--profile=studio --channel=v06`，版本 0.6.0，端口 55061、设备目录和数据均独立。仍属于隔离候选，不是已签名的跨设备正式发行。
