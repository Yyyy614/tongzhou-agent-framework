# 员工账号与第二台电脑

账号属于公司员工，设备登录凭证属于每台电脑。**同一员工换电脑后使用同一个 Agent 和已有记忆；不同员工的记忆和权限保持隔离。**每次模型用量仍按执行员工/Agent记账。

本轮 HTTPS 测试入口为 `https://agent-test.example.com:8443`。443 上原有网站保留；8443 由独立测试代理容器提供，员工客户端不再依赖 SSH 隧道。2026-11-13 经用户确认，仅新增全部 IPv4 来源的 TCP8443 入站允许规则；公网证书校验、健康检查、员工登录和原生 Harness 任务均实际通过。

## 管理员准备

1. 在管理后台创建员工，员工编号就是登录账号；选择岗位预设，分配插件与明确权限。
2. 员工管理 → 对应员工 → 员工接入，生成一次性激活码，交给对应员工。
3. 从管理员下载按钮获取 **HTTPS账号版员工 ZIP**，或者使用工作区 `.local/staging/employee-client-https-release.json` 指向的发行 ZIP。不要拿旧的127.0.0.1隧道版包去另一台电脑。

管理员仍使用受保护的短时管理入口，本轮新增的是员工账号密码登录，不是开放注册或共用公司密码。

当前工作区可双击 `.local/云端测试后台.cmd` 打开管理后台。该操作员入口仍通过已有管理 SSH 连接签发短时登录票据；不要把该脚本、管理私钥或工作区私密目录分发给员工。

## 首次设置密码

1. 解压整个 CompanyAgent 文件夹，双击“启动员工Agent.cmd”。公司地址已配置在包中，不需要员工输入 SSH、API Key 或服务器密钥。
2. 选择“首次接入 / 重置密码”，输入管理员给的码，设置自己的12至128字符密码，填写电脑名称。
3. 登录后界面显示账号和所分配的岗位，点击“打开 Harness”。工作仍在原生 Harness 内进行。

如果之前只用旧激活码登录过，尚未设置密码，请管理员重新签发一次码，通过上述流程设置密码。已有 Agent 和记忆不会因此重建。

## 在第二台电脑测试

1. 仅复制/下载同一份 HTTPS账号版 ZIP 并解压，**不复制第一台电脑的 identity.json 或用户数据目录**。
2. 双击“启动员工Agent.cmd”，直接输入同一个员工账号和密码，为第二台电脑起不同名称。
3. 打开自己的岗位，读取同一条私人笔记，完成一次任务；管理后台检查该员工的新设备、任务日志和模型用量。
4. 再用另一位员工账号验证岗位和私人记忆隔离。换电脑不会创建一个新员工，也不会把其他人的记忆加载进来。

每个员工最多5台有效设备，设备凭证30天到期，本机由Windows DPAPI保护。客户端保存设备凭证，不保存登录密码。

- 本机另增 `test-employee` 独立测试账号，桌面“本机隔离测试Agent”快捷方式已实际启动并重开原生客户端。独立目录为 `.local/staging/isolated-test-employee`，连接同一公网HTTPS测试服务。真实原生任务完成插件、私人记忆写入和报告；关闭重开后全新会话实际读回 `PRIVATE_TEST`，两轮共7次模型请求。其他员工的既有设备身份摘要未变化，跨员工/管理员接口403。证据为 `.local/staging/isolated-native-smoke.json`。

- 同一台电脑的两份全新设备配置分别注册/登录同一员工账号，获得不同设备ID和凭证，读取同一个私有记忆；另一员工的记忆和管理接口访问被拒绝。
- Windows 原生 Harness 通过公网执行任务 `6fefaac5-1273-44e4-80dc-7f98f4e4a353`，插件、私人记忆读取、报告回执成功，7次模型请求及用量归属可查；另一设备配置可读取该账号的结果。
- HTTPS 管理会话 Secure Cookie、跨来源写拒绝、匿名下载安装包拒绝及管理员下载接口均通过。
- 原有443首页内容摘要一致，11个线上容器的ID、启动时间和重启次数一致。测试应用和数据库健康，测试网络只有3个本项目容器。

证据为 `.local/staging/account-two-profiles-smoke.json`、`account-native-https-smoke.json`、`console-https-smoke.json` 和 `deployment.json`。两份配置在同一台物理电脑上运行；**实际第二台电脑尚待按上述步骤验收**。

## 退出、撤销和忘记密码

- 退出当前电脑只撤销当前设备，之后可用账号密码再登录。
- 管理员可以单独撤销任意设备，该设备后续请求会被拒绝。
- 忘记密码由管理员重新签发一次性码，员工自己设置新密码。**真正提交新密码后，旧密码、旧设备和旧后台会话失效。**签发码本身不会立即退出正在工作的电脑。
- 账户停用、岗位/插件授权和记忆ACL仍由原内核实施；密码登录不会扩大权限。

服务端使用随机盐scrypt保存密码验证信息，数据库限流跨进程重启保留。登录错误不区分账号不存在、未设置密码或账号停用。密码散列工作有并发上限，避免挤占共享服务器资源；请求过于频繁时须稍后重试。

该版本仍是受限测试环境。证书副本仅在服务器测试目录中使用，来源为同域名现有有效证书，未修改原证书或原站点配置；测试代理的证书更新需要单独刷新副本并重新加载测试代理。生产SSO/MFA和自动升级仍未实现。
