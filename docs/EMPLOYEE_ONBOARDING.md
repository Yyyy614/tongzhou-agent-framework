# 员工接入与本机验收

本轮已与用户确认：先完成本机验证，不配置公网或跨电脑部署。采用独立员工发行包、独立设备目录和真实原生 Harness，尚未在第二台实体电脑验收。

## 管理员操作

1. `npm run console` 打开管理后台，在“员工管理”新增员工，选择部门、角色、允许的工具和本人记忆/报告能力。
2. 在“Agent 管理”创建 Agent，负责人选择该员工，固定岗位预设与插件版本，配置允许的工具和服务。权限取员工、Agent 和启用插件的交集，预设本身不提权。
3. 返回员工行，点“员工接入”。分配有效岗位后生成一次性激活码，复制后交给该员工；不会自动发送平台消息。
4. 同一弹窗可下载客户端 ZIP、查看已激活电脑、撤销设备。分发公共 ZIP，不分发员工激活后的数据目录。

激活码随机生成，24 小时有效且只能使用一次；服务器仅保存摘要。重发会作废该员工尚未使用的旧码。每名员工最多五个有效设备，名称用于识别电脑，不授予权限。

## 员工操作

1. 解压完整 Windows x64 包，双击 `启动员工Agent.cmd`。包内已有 Node 和固定版本官方 Harness，无需开发仓库、数据库或服务端 `.env`。
2. 首次在本机接入窗口填写激活码和电脑名称，只会显示本人已分配的有效 Harness Agent。
3. 选择岗位，点击“打开 Harness”。实际工作在原生客户端完成，接入窗口负责激活、选择岗位、关闭和退出。
4. 下次启动保留登录与原生历史；重复启动复用现有本机接入服务。岗位或权限调整后关闭并重开 Harness。

设备身份有效期 30 天，以 Windows DPAPI 绑定当前 Windows 用户加密保存。优先 PowerShell 7，缺失时使用系统自带 Windows PowerShell 的同一 DPAPI 命令兼容。模型总密钥只在服务端；原生两小时连接凭证固定到员工与 Agent，位于该用户的独立配置目录。

默认数据位于 `%LOCALAPPDATA%/CompanyAgentFramework/<服务标识>`。笔记版本、任务、日志和账本以公司服务端为权威；原生历史与缓存留在本机。不要复制用户数据目录，不将共享一个 Windows 账号视为 OS 级员工隔离。

撤销设备后，原令牌及其派生后台会话、Harness 连接的后续请求失效，已完成动作不回滚。接入窗口可关闭失效的 Harness，再用新码激活。员工主动“退出这台电脑”会撤销设备并移除本地长期身份，之后也需新码。

## 当前电脑体验

```powershell
cd C:\projects\tongzhou-agent-framework
pwsh -NoProfile -File scripts/start.ps1 -SkipBuild
npm run console
npm run employee:demo
```

最后一条打开已配置的验证员工甲；也可双击 `.local/员工接入体验.cmd`。此入口仅用于当前电脑，公共发行包没有内置验证员工或凭证。

`npm run build` 后运行 `npm run build:employee-client` 生成公共包。`.local/employee-client-release.json` 保存最新 ZIP 路径、服务地址与 SHA256，不含登录凭证。构建使用全新目录与文件白名单，不压缩工作区或用户 profile；后台下载只对管理员开放。

## 跨电脑的后续条件

当前 `http://127.0.0.1:4317` 只连接这台电脑。跨电脑前需要可访问的 HTTPS 服务，服务端 `.env` 配置 `PUBLIC_ORIGIN=https://实际公司地址`，并以 `npm run build:employee-client -- --server-url https://实际公司地址` 重新生成包。

PUBLIC_ORIGIN 决定返回给原生客户端的模型/MCP 地址，不信任客户端 Host 头。外部地址只接受 HTTPS，HTTP 仅用于 loopback。配置变量不会自动部署服务、签发证书或开放防火墙；本轮均未执行。SSO、IM 与统一更新发行也未完成。
