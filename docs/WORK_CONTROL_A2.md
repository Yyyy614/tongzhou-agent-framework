# A2工作控制：停止、等待、人工决定与恢复

本轮在A1基础上实现，使用新的本机隔离目录/数据库schema。保持通用Work/Task/Run、插件和岗位边界，不部署服务器或迁移旧数据。

## 必须成立的行为

- 停止/等待先持久变更控制代数，关闭新模型、工具和宿主服务动作的准入；正在执行的调用可以收尾。只有当前任务和已准入动作全部收尾后才确认stopped/waiting。外部结果未知时进入reconciliation_required，不假称停止已确认。
- 工作级等待保存waitReason、问题/人工请求和责任；不占执行槽让模型空转。停止、等待、人工决定均有版本和幂等回执。
- 只有显式、当前有权的人工决定能恢复；创建新的Task/Run和轮次，保留旧终态/报告/审核。停止后新旁观消息不恢复工作。
- 同一恢复链中，相同岗位、工具和规范化输入标识同一逻辑副作用；已确认结果复用原回执，未知结果阻止重放。只读查询可重新读取最新状态。变更后的写输入仍要求新的精确写审批，不承诺任意外部系统全局恰好一次。
- 重启后已运行但未确认的Task/动作转待核实，未执行的排队任务不越过工作控制；先核实旧执行环境/回执，再批准恢复。
- 人工核实需独立审核权限、具体理由和证据引用；记录“人工确认”的来源，不伪称宿主已经验证外部业务事实。

## 拟验证的完整路径

1. 初轮先完成一次受控写动作，第二个动作执行中请求停止；停止提交后新动作被拒绝，已准入动作收尾后确认停止。
2. 负责人显式恢复原工作；已确认动作返回旧回执，剩余新动作才执行，旧Task/Run不覆盖。
3. Agent或负责人请求人工等待；保存问题，释放执行，人工补充后用新Run继续。
4. 动作执行后、确认前中断；重启标记未知，不能自动重放；人工核实后恢复，已发生的动作仍只执行一次。
5. 并发停止/旧revision/重复决定、撤权、跨公司、原预算继承和旧API回归。

已发出到外部系统的调用无法靠模型“撤销”，本框架只确认可观测边界内的收尾与回执。

## 已实现的内核与接口

| 接口 | 用途 |
| --- | --- |
| `POST /v1/work/:id/control` | `stop / wait / resume`，必填revision、idempotencyKey、reason；resume提供原参与岗位范围内的assignments |
| `GET /v1/work/:id/control` | 当前控制、动作账本与人工决定；优先当前未知/执行中动作，最多256条并标明截断，最近控制128条、核实256条 |
| `GET /v1/work/:id/actions/:actionId` | 受权查看所选动作的输入、回执、确认来源和最近32次尝试；输入超过32000字符明确截断，账本另提供240字符预览 |
| `POST /v1/work/:id/reconcile` | 独立审核人提供理由、证据引用，确认unknown动作成功/未执行，或确认中断旧任务的执行端已经关闭 |
| 受管MCP `work_wait` | 当前任务所有者提出human_decision/dependency/environment_unavailable和具体问题，持久等待并释放执行 |
| 受管MCP `work_checkpoint` | 恢复时按需读取本人成功任务摘要及本人已确认动作引用；最多32条动作、每条1000字摘录，不带其他岗位正文 |

WorkControl、WorkActions、TaskQueue和HarnessRuntime共同执行控制。Task/Run保留原表、原ID；恢复采用A1新轮次，不复活旧Task。`work_controls / work_actions / work_action_attempts / work_reconciliations`保留决定、逻辑动作、每次真实尝试及人工来源。启动恢复只取消孤立队列信封、标记未知，不删除原记录，不自动重放。旧A1 active/空控制字段保留原revision计算，所以已有多轮审核仍有效。

状态流为active → stop_requested → stopped或waiting；不可信回执/中断进入reconciliation_required。未收尾不确认停止；远端接受取消也不等于已停止，拒绝取消、未知终态或超时均需核实。控制先提交持久栅栏，再请求执行端退出；模型代理、MCP、插件派发和嵌套宿主服务重新检查。旧Task/Run和动作尝试只能在仍running时提交终态；迟到动作回执追加为证据，不覆盖人工决定。

关闭既有工作按当前公司和管理范围鉴权，即使来源能力已撤销或目标岗位停用，管理员仍能停止并查看账本；恢复继续检查有效员工、岗位、原来源派工能力和原参与者范围。普通员工可请求自己的任务等待，模型没有恢复工具。核实需要独立team.review；纯审核人可读账本/动作参数和提交核实，不因此获得派工、停止、恢复权，UI分别使用canControl和canReconcile。管理员沿用既有管理核对权限。部分参与者只见安全状态，不从工作详情或收件箱取得其他岗位控制正文。

动作参数可见性不替代私人记忆ACL。内置memory_write及精确安装工具中显式声明记忆Host服务的能力（包括标准@company/private-memory:notes.write；旧0.1副作用工具保守采用包级记忆声明），输入预览、完整参数和成功回执另走原有authorizeMemory检查；只有team.read/team.review的负责人会看到inputRestricted，不会得到笔记正文/来源。人工确认此类动作成功也需独立记忆读取授权。此处只保护框架已知的私人记忆能力，不将其冒称任意第三方插件数据均已具备完整资源标签与派生ACL。

同一恢复链的逻辑动作身份是workId、action_scope、agentId、精确工具版本和规范化输入摘要。只拦截有副作用的host/write工具，只读工具按需重读。相同身份成功后复用回执，不再次执行或消耗一次写审批；有意重复的业务动作必须在输入里提供新的业务操作身份。改动写入参数仍需精确审批。插件回执在人工核实和复用时同样验证成功outcome、Receipt与已安装输出Schema；停用能力不妨碍读取原Schema验证历史回执，但仍禁止实际新调用。人工确认保留source=human，无法由框架凭空验证外部业务事实。
