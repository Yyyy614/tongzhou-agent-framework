# 本机管理后台

后台与现有内核同源运行在 `http://127.0.0.1:4317/`，不需要另起前端服务。静态页面在 web/，管理与会话接口在 src/admin.ts、admin-observability.ts、console-auth.ts；工具、记忆和账本继续使用原内核。

云端独立测试环境使用同一套界面，入口与账号见 [ACCOUNTS.md](ACCOUNTS.md)。2026-11-13 的自动更新增量已经部署到该测试环境。

## 自动更新与保留选择

- 独立记忆、日志和用量页在可见时每3秒检查一次数据。切回页面会立即检查；隐藏的标签页暂停网络轮询。界面展示自动更新状态和最近成功时间，更新不会重建筛选栏。
- 当前员工、Agent、日志事件/已提交搜索、历史游标、用量时间范围、当前笔记和预览模式保存在当前标签页的sessionStorage中，并按管理员身份与公司区分。页内切换、右上角刷新和当前页F5都会保留选择；只保存界面偏好，不保存笔记内容或认证凭证。
- 记忆只有版本变化时才更新编辑器。有未保存草稿、正在保存或打开对话框时暂停自动刷新；请求发出后才开始输入也不会被迟到的响应覆盖。保存或明确放弃草稿后恢复。右上角刷新同样保护草稿；“重新读取”的放弃确认仍由用户决定。
- 浏览更早的日志时暂停自动插入新记录，保留当前历史页；“回到最新”恢复自动更新。未提交的搜索文字也不会被自动当作查询条件。
- 临时连接失败会保留已有数据和选择，并退避重试；登录失效或失去访问权限时退出当前数据视图并停止轮询。自动刷新仅调用已有读取接口，不会调用模型或增加模型用量。

真实验收：原生Harness任务 `7f21fe78-1aa6-4cf9-8546-110ea04bc69f` 将测试员工PRIVATE_TEST从v1写到v2并提交报告，后台未点击刷新就显示新记忆、日志和由7增至11的模型请求数，员工和岗位选择不变。证据为 `.local/staging/console-live-native-smoke.json`。浏览器夹具检查另外覆盖草稿竞争、晚到请求、历史分页、断线恢复和会话失效；夹具不等同于真实模型任务。

开发者可使用现有Playwright运行 `npm run test:console`；若由宿主提供模块，通过 `PLAYWRIGHT_MODULE_PATH` 指向其Playwright包。该验证使用真实页面和独立loopback API夹具，不向模型或业务系统发请求。

## 打开与登录

```powershell
cd C:\projects\tongzhou-agent-framework
pwsh -NoProfile -File scripts/start.ps1
npm run console
```

`npm run console` 会签发一个 10 分钟内有效、只能使用一次的本机入口，并打开系统浏览器。入口在页面加载后立即从地址栏清除，后台使用 8 小时 HttpOnly、SameSite=Strict 会话；退出后会话立即失效。员工被停用后，既有会话也不再有效。启动脚本和聊天不会打印登录令牌。

也可以在登录页填写已有平台访问令牌，不能使用 DeepSeek 模型密钥登录。开发身份：admin 为管理员，alice/bob 为验证员工。`npm run console -- alice` 可验证员工无管理权限的状态。正式企业 SSO 尚未接入，本机命令签发入口属于可信开发操作。

## 可操作内容

| 页面 | 已接入能力 |
| --- | --- |
| 工作空间 | 员工、Agent、插件、模型请求真实统计；每日趋势、最近运行和快捷入口 |
| 员工管理 | 新增、编辑、授权、启停与筛选；员工接入、一次性激活码、客户端 ZIP 下载及设备撤销 |
| Agent 管理 | 创建岗位、绑定负责人、职责与配置、插件版本、记忆服务授权、启停和运行验证 |
| 插件与能力 | 安装已审查本机包、schema/初始化健康验证、挂载与额外挂载移除、精确版本启停 |
| 独立记忆 | Agent 空间切换、笔记索引、新建、编辑、预览、双链跳转、来源和版本保存 |
| 日志与记录 | 按 Agent、事件和关键词查询；详情和游标分页；管理动作可追溯 |
| 模型用量 | 7/30/90 日、员工和 Agent 筛选、每日趋势、归属及单请求详情 |

工具验证按岗位所有者授权执行，不因为管理员打开后台就扩大员工能力。模型任务入口需要明确确认，任务经现有队列执行，用量归属执行员工，并保留发起者。

员工无需持有管理员开发文件。分配有效 Agent 后，在员工行点“员工接入”，签发激活码并下载独立客户端；撤销设备会拦截其派生会话和原生连接的后续请求。详见 [EMPLOYEE_ONBOARDING.md](EMPLOYEE_ONBOARDING.md)。

## 配置与保护

- 员工与 Agent 修改带 revision；旧页面不会静默覆盖更新后的权限。当前管理员不能在当前会话里停用或降为员工。
- 插件先声明能力；员工和岗位分别授权，界面显示实际可用工具数。停用插件后，可用工具数同步减少。
- Agent 的负责人在后台创建后固定。人员交接应新建 Agent，避免把私有记忆悄悄转移；专门交接流程后续实现。
- 活动运行期间不能修改岗位配置。停用是撤权动作，拦截后续操作；不撤销已经完成的外部动作。
- 记忆保存期间锁定编辑输入；冲突保留草稿。重新打开笔记后，旧请求的完成不能覆盖新编辑器。
- 未改变目标和输入的验证重试复用同一幂等键。无法确定写请求回执时显示待核对，不伪报成功。
- 后台仅展示 Token 用量。缺失用量、远程上报、服务商实测分别标记；金额费率未配置，不显示虚构费用。

本轮浏览器验证创建的“后台验证员工”“框架验证助手”和 `@example/console-check` 均已停用，保留其记忆、配置和审计，可查看验证轨迹。它们是通用框架夹具，不是实际公司业务数据。

## 通讯平台后续接入

钉钉、飞书、企业微信可以各做渠道适配器，共用当前框架。建议分别处理企业/人员身份映射、组织同步、消息与文件输入、任务触达及回执，再映射到公司主体和任务；不能直接信任外部消息中填写的员工编号。

外部身份采用 `(platform, tenantId, externalUserId)` 映射到内部员工。消息事件先校验平台签名、租户和去重标识，再生成可信任务；平台凭证留在服务端。每个平台能开放哪些登录、组织、消息和待办功能，需要按应用类型与平台授权逐项验收。

目前页面明确显示三个渠道“尚未接入”，本轮没有发送平台消息、同步通讯录或连接业务系统。参考各自官方文档：[钉钉](https://open.dingtalk.com/)、[飞书](https://open.feishu.cn/document/client-docs/intro)、[企业微信](https://developer.work.weixin.qq.com/document/)。
