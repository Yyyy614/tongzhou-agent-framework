# Harness公司发行版与独立插件验收

本轮仅在本机隔离环境开发验收；原0.3客户端、现有数据、服务器测试发行及线上业务不替换、不迁移、不删除。员工可继续使用旧入口，另提供明确标记的新隔离体验入口。

## 交付依赖

1. 固定上游源码及构建环境，核查原生欢迎页、工作区扩展和账号生命周期接口。
2. 分离可复用的公司设备/岗位服务与旧启动器逻辑。登录、岗位切换、授权更新和退出由公司宿主控制；总模型密钥不进客户端。
3. 在Harness公司发行中提供公司账号登录、岗位选择/切换和工作中心，进入工作台不用拉起第二个桌面应用。优先使用插件扩展；必要的上游源码补丁固定、可复现，并保留许可。不得通过修改官方签名安装、窗口嵌套或自动点击伪称完成。
4. 新旧设备目录隔离。账号/岗位切换不得串用记忆、工具、历史或运行身份；活动工作必须停止并确认后切换。重新登录、网络失败、退出及撤权应有明确状态。
5. 独立开发一个不在内核目录中的业务能力包，用公开插件契约安装/授权/挂载/执行/升级；换包/换岗位只改配置。记录操作前后src摘要，证明业务接入无需修改内核。验证旧包继续工作、未授权工具拒绝、个人记忆隔离与审计归属。
6. 构建独立Windows可运行包，在隔离服务与真实桌面验收公司账号流程、两个岗位切换、工作中心和真实Harness工具调用/用量；付费模型证据与受控HTTP测试分开。

## 验收与界限

- 新行为先公共接口失败测试，再实现、定向回归；最终check/build/test及真实桌面检查。
- 普通员工只有一个应用入口，账号页和工作区属于同一公司Harness应用；后台子进程不等于外置启动器。
- 上游补丁、构建命令、版本和摘要可追踪。若环境或上游接口存在阻塞，记录实际证据，不将套壳或文档称为完成。
- 本轮不接真实业务平台、不发送外部消息、不启用生产自动更新、不覆盖旧桌面入口或云端发行。
