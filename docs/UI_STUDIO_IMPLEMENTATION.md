# 公司工作台：真实集成验收

选定：A管理后台+C员工Harness，银灰/青绿统一主题，macOS式清晰分栏和工具层次。不是静态原型替换。

## 工作项与依赖

1. 新增显式studio Web配置与共享视觉令牌。classic默认保持原样，旧本机服务/云端发行不切换。
2. studio管理壳、工作优先首页、分组导航、检索；员工/岗位/插件/权限/记忆/日志/用量/协作/机器人连接继续访问现有真实API。刷新保留筛选和编辑草稿。
3. 公司账号与选岗页接入同一主题；原生工作中心采用C布局。本人记忆、能力、任务、提醒、连接与核对/工作控制通过公司IPC白名单走真实服务；聊天进入真实Harness对话，不制造模型回复。
4. 独立本机4917服务、新root/schema、新账号与设备目录；构建到新app目录，不覆盖旧发行或旧设备。以现有独立插件验证通用框架。
5. 真实浏览器/原生Electron验收：管理员创建与配置员工、员工登录选岗、原生模型回合、本人记忆、任务核对/停止等待恢复、后台日志用量、断网/权限拒绝和刷新草稿。运行检查、相关/完整回归与两轮视觉打磨，提供可直接打开的入口。

## 共同规则

- 身份授权与状态由后端判断；员工不能从UI扩大岗位或私人记忆访问。
- 不在前端放模型/应用总密钥，设备令牌仍由原生安全存储保护。
- 副作用操作使用当前revision与稳定请求键，未知结果不能换键自动重放。
- 中文工作状态与名称优先，底层编号在需要复制或排查时展示。
- 实测、上报和未知计量分开；机器人配置/授权/连接/员工绑定分步表示。
- 小屏、键盘焦点、减少动态效果、较高对比度和选择/草稿保留都需要实际验证。

- 原生真实登录与岗位切换、记忆/能力/用量隔离、工作详情/历史、本人工作等待/停止/人工恢复均通过；错误密码后保留账号并清空密码，可直接重试。窄窗口内容宽度725px、滚动宽度725px，无横向溢出。`native-qa.json`记录14项通过及无页面异常。

## 隔离与打开方式

- 本机新服务 `http://127.0.0.1:4917`，服务 root 为 `.local/ui-integrated/host`，数据库 schema `fw_be5f825757af85`。旧4417服务 schema为`fw_79515389048656`，不同。
- 新应用 `.local/ui-integrated/app`，新设备 `.local/ui-integrated/device`。旧构建和旧设备目录保留。classic 的5个主要Web文件及原生主进程/预加载文件与本轮基准哈希相同，证据`preservation.json`。本轮没有执行服务器部署或云端数据操作。
- 桌面新入口：**公司 Harness - UI隔离测试**、**公司管理后台 - UI隔离测试**。后者每次生成隔离服务的一次性管理入口，快捷方式本身不含密码或访问令牌。
- 服务需重启时：在项目目录运行 `npm run studio`。打开管理端运行 `npm run console:studio`；构建此候选运行 `npm run build:harness:studio`。员工快捷方式直接启动真实 Electron 应用，登录/选岗在 Harness 内完成。

该版本是本机隔离候选，没有替换云端、旧安装包、签名发行或自动更新渠道。安装包/云端UI发布应在本轮体验确认后，使用现有独立测试发行流程进行；公司原有数据无需迁移或清空。

## 0.6 隔离候选的比例与视觉层级修正

本轮使用 `.local/v06` 的工作树、服务、数据库与设备空间，未修改上述旧候选或线上。账号、任务、资源、独立记忆和用量记录继续保留。

- 运行窗口跟随 Windows 原生显示缩放。本机实际为 150%，应用缩放 100%；验收和预览入口均不使用 `--force-device-scale-factor=1`。
- 共享字号令牌在 `packages/company-ui/tokens.css`：页面标题 30–32px，区块标题 20–22px，卡片标题 18px，正文与输入 16px，常用按钮 15px，辅助信息 14px，时间、版本与状态 13px。窄窗口通过布局调整适配，正文不缩小。
- 页面主要按钮高 48px，普通表单按钮 44px，桌面表格行操作 36px。核对结果使用局部强调；编辑、历史和控制操作为次级；停用操作单独标色。长工作标题保留完整文字，使用卡片级字号，避免压过页面和区块标题。
- 后台侧栏的导航独立滚动，账号保持可见；岗位卡片操作允许换行；工作表格在自己的容器内横向滚动。Harness 按实际面板宽度调整双栏、能力卡片和导航，长标题不挤压关闭按钮。
- 修正普通员工查看工作详情时误请求管理控制记录的问题：先读取服务端的权限标记，有控制或核实权限才读取相应记录。后台继续执行原有授权检查。

实际检查覆盖原生 Harness 的常规与 800px 窗口、账号选岗、工作结果与历史、市场、记忆、用量；后台的 1440/1024/760px 看板、员工编辑弹窗、岗位卡片和工作表格。Windows 原生 150% 缩放的实际窗口也已检查。员工完整结果可读，未再显示多余的权限错误；记忆岗位、日志过滤和用量员工/岗位选择在自动刷新后保持。

`pnpm check`、`pnpm build`、原生 Harness 构建及相关 4 文件 / 10 项测试通过。视觉检查为真实浏览器与 Electron 验收，不将自动单元测试当作视觉验收；本轮未新增真实模型调用或业务写入。截图与检查记录保留在工作树忽略提交的 `.local/v06/ui-*.png`、`.local/v06/ui-hierarchy-qa.md`，命令日志在主工作区的 `.local/v06/ui-hierarchy-*.log`。
