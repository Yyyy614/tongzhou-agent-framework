# 下一版：组织协作与工作辅助 Bot

用户已授权实施。延续现有宿主、Harness、员工账号和插件架构；业务逻辑通过插件接入。部门、员工长期Agent和临时子任务是不同对象。

## 本轮验收

1. 管理员维护部门树、直属上级和管理范围。业务负责人仍是employee，显式授予团队查看/派工/核对能力；预设不授予权限。拒绝组织循环、跨公司关联；组织变动后重新校验范围。团队摘要不开放私人记忆或全部聊天。
2. 负责人创建一项协作工作，派给多个已授权Agent；执行主体为各Agent所有者。复用持久队列、模型网关和计量；支持并行、幂等、期限、责任人、结果汇总和人工核对。结果不确定保留待核对，失败不能被汇总成全部成功。
3. 工作辅助Bot面向通用任务、提醒和问题事件。提醒持久化，到时投递内部收件箱；事件可关联外部subjectRef，按已授权目标创建协作工作。自动处理受挂载工具与权限限制，候选结果可交人工核对。真实客户、销售、财务和通信平台仍通过独立适配器连接。
4. 统一工具/任务/事件/提醒的身份、关联编号、幂等键、状态和结果回执。提供可运行的通用工作辅助插件及开发者契约检查入口；保留0.1插件和已有任务接口兼容。
5. 员工启动使用规范化的独立目录；公司插件链接正确、首次岗位预设可用，不能静默以默认无限制模式代替公司连接。登录和设备隔离沿用现有实现。发行包含清楚的错误提示和一键启动，不依赖开发工作区路径。
6. 后台可操作部门/汇报关系、派发协作工作、查看汇总和核对、管理提醒。员工能从自己的Harness/接入窗口查看本人工作和到期提醒。只保留已授权摘要及引用，继续按需读取记忆。

## 边界与规则

- API调用者来自实际认证；插件宿主服务还需插件声明、员工授权和Agent授权的交集，不能从参数冒充主体。
- 部门树描述组织；managerId描述人员汇报线。teamScope为直属或全部下级的数据范围，操作授权独立。
- 工作分配的队列任务以员工身份执行，保留发起者；聚合只读取这项工作产生的任务结果。
- 人工核对是明确记录的决定，不伪称已经发布外部业务结果；外部写工具继续遵守精确输入的一次性审批。需要真实业务接口后才能验收客户消息或业务发布。
- 提醒投递到内部收件箱，不假称已发钉钉/飞书/企微。事件来源、处理人和subjectRef命名空间均由可信适配器绑定。
- 先验收本机新版本，再更新独立云端测试服务。保留旧发行与备份，检查现有线上站点与容器，遇到活动测试任务先等待完成。
