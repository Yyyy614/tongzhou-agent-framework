# 0.7 工作记忆与上下文治理

基线 `041f2fd`，分支 `feature/work-memory-context-governance`。按用户确认的六步方案直接实施；保留 0.6 客户端、数据与线上环境。行业规则继续留在插件。

目标：输入归属到工作后恢复有限的事实和笔记，按权限逐步读取资料；成果继承实际输入的可见约束，界面能解释来源、覆盖与省略。

## 必守契约

1. ResourceRef 保持 `{id,version}` 兼容，增加的来源和授权信息由宿主解析。
2. 来源记录来自实际模型输入、授权资源/记忆读取和公司工具回执。模型引用可以补充证据，不能删除宿主依赖。
3. 自动生成内容的接收者必须能读取全部依赖。未知来源默认只给执行本人；不自动扩大旧报告可见性。控制状态独立于私有内容。
4. 记忆键包含公司、工作、执行身份和岗位；笔记不能覆盖状态、审批或执行回执。接续沿用原工作及 A2 幂等机制。
5. 不暴露隐藏资料的标题、数量或存在性；无匹配、可见域索引落后、来源不可用、预算截断有不同反馈。
6. 模型窗口先给约束、输入和状态，其次工作笔记，再给本轮资料；输出与工具回执空间单独预留。
7. 派生失效保留原记录；新任务不得把旧结论当作当前事实。共享经验复用现有审核发布入口，不另建一套市场。

## 隔离验证

在独立 `.local/v07/worktree` 和新测试 Host/schema 下使用两个员工岗位、一个负责人、通用资料域；复用本地 PostgreSQL 服务但不复用旧 schema 或设备身份。测试资料仅为合成数据，不发送真实平台消息。

验收覆盖：大量其他人的记录不挤掉本人资料；公开引用不能洗白私有输入；重启恢复与双工作隔离；按需跨域召回和覆盖说明；撤权、停止、乱序与重复事件；实际模型请求与来源清单一致；检索/摘要/执行用量归属；上下文解释遵守原有 ACL。

### 兼容接口与归属

- `GET /v1/resources` 增加 `limit`、`cursor`，保留原字段；结果增加 `hasMore`、`nextCursor`。游标不能跨调用人或查询复用。
- `GET /v1/work/:id/memory/:agentId` 返回宿主事实和本人可见笔记。负责人默认只有控制投影，组织上下级权限不自动授予私人笔记权限。
- `PUT /v1/work/:id/memory/:agentId` 接受 `expectedRevision`、`idempotencyKey`、`goal`、`decisions`、`blockers`、`nextSteps`、`artifacts`，拒绝状态/身份等额外字段。
- `POST /v1/agents/:agentId/work-context` 解析显式工作、入口绑定或候选；不隐式恢复已停止工作的执行。
- Harness 的 `work_memory_read`、`work_memory_save` 始终绑定宿主当前工作与身份。模型不能指定其他员工、岗位或冒充管理员；幂等键由宿主生成。

DeepSeek Harness 继续负责交互和执行；上述权限、持久工作记忆、来源追踪、结果保留和用量归属在宿主内核。通用合成任务及 conformance 插件只用于验证，未引入部门业务规则。

## S3—S6 完整实现

在原内核上补齐可见资料域与可信 `MemorySource`、中英文按需召回、索引覆盖水位、实际模型请求窗口与共享读取预算。来源账本同时覆盖独立笔记、工作笔记、刷新上下文新召回的资料、插件结果和 checkpoint 展开内容；报告的旧事实不再进入当前结论摘要。

资料变更在同一事务产生索引 outbox，重启、重复和乱序按权威当前版本处理；关联订阅持久通知或受限执行，不默认唤醒全公司。经验沿用内部市场的候选、验证、独立审核、限定发布及停用流程。

Harness 新增“工作依据与记忆”，后台新增“上下文与资料域”：实际来源、版本、遗漏、预算、本地处理与模型费用分项、工作笔记及候选经验均接真实接口。自动刷新保留筛选和未保存输入；撤权或版本变化收起旧正文。失效工作笔记可从新证据受限重建，停止与控制代数在入场、发送模型和保存事务内检查。

Windows 0.7 发行包连接独立测试服务，采用独立安装 GUID、快捷方式、任务栏身份和设备目录。测试服务器的独立应用、数据库、存储卷和 `/v07/` 路径保留原 443、8443 首页及 `/a2/` 入口。业务样例仍在插件中，未写入内核。
