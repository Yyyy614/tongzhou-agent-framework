# Harness 与 Bot 验收记录

日期：2026-11-13。环境为 Windows、Node 24.17、项目专用 PostgreSQL 18.4，官方签名的 Harness Desktop 0.2.2-rc.2。二进制未修改；版本与 SHA256 固定在 `harness-desktop.lock.json`。这是原生插件和预设扩展的框架开发版，尚未制作公司品牌安装包。

## 实际桌面验证

用 Playwright Electron 启动真实的官方 EXE，使用独立 DSH_HOME 与 Electron 用户目录。插件界面确认公司连接包的岗位预设、连接组件均为“运行中”。岗位员工使用公司工具，而非编程任务。

- 运行：`e67aef61-a47d-40b9-9728-ad134601f28d`。
- 持久任务：`0f82db6e-daa1-4905-92f4-c69e3986c8ea`。
- 实际调用通用 normalize 插件、本人 `memory_read(INDEX)`、`report_record`，最终输出“公司 框架 已接通”，状态 succeeded。
- 三次真实 DeepSeek 请求；公司账本记录 provider usage：1,800 输入、255 输出 tokens。客户端自己的展示口径不作为公司计量依据。
- 独立审计包含插件成功、记忆读取、报告写入与运行成功。未写入或修改记忆。
- 证据为忽略提交的 `.local/native-harness-smoke.json` 与 `.local/native-harness-success.png`；不含密钥。

曾发现原生插件未运行：测试额外安装的依赖掩盖了 profile 依赖路由问题。移除该测试依赖后复现失败，把受管包部署到 profile 内后同一测试及原生界面通过。最终用例不再依赖测试专用安装。另验证官方打包客户端实际采用 `--user-data-dir` 指定的目录。

交付时再通过实际 `node scripts/harness.mjs` 启动，发现 Windows 隐藏进程参数也隐藏了原生主窗口；调整为只隐藏 Web 后台进程后，确认原生主窗口句柄非零、标题为已验证的对话。标准启动器现已保留可见客户端运行；关闭窗口后连接凭证由启动器回收。

## 自动验证

`npm run check`、`npm run build` 成功。完整回归 32 个文件、40 项通过，使用真实 PostgreSQL；Harness 集成实际启动 SDK 进程，模型端为本地可控 SSE 夹具。这些自动用例与上述真实付费验证分别记录。

新增覆盖包括：预设不隐式提权、实际原生依赖解析、私有配置保留、消息并发去重与身份防冒用、会话/回合隔离、准入等待中取消不派发模型、工具未收尾不释放占用、正常与异常结束禁止新工具、未知回执优先、连接额度、权限版本失效、原生持久父任务、跨岗位委派权限与共享预算。取消和竞争边界主要由数据库/HTTP 行为测试验证，未声称所有原生按钮和平台消息场景均已人工验收。
