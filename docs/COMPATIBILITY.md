# 0.1 本地兼容与验收记录

日期：2026-11-12。实际测试 Windows、Node 24.17.0、TypeScript 6.0.3、PostgreSQL 18.4、pg-boss 12.38.2、Fastify 5.12.8、Harness SDK/运行时 0.2.2-rc.2。所有 Node 依赖以 pnpm-lock.yaml 固定。

## 已有真实证据

- 模块插件进程与远程 JSON-RPC 服务可用同一份包格式挂载。
- 真实 PostgreSQL 测试：身份、权限、记忆版本、幂等、队列重启、并行派工、审批、定向发布与回滚。
- 真实 Harness 进程测试：MCP 插件工具调用，关闭 shell/文件工具，受控模型请求和逐员工 usage。模型端使用本地可控 Messages SSE 夹具。
- 真实 DeepSeek smoke：运行 `6570a448-1f32-4eb8-8cb7-581db7fe876d`，输出“Harness 已接通”，完成插件、记忆读取和报告；5 次请求，1,774 输入和 310 输出 tokens。原始凭证不进入报告。
- 最终版本真实 smoke：`46767ded-3c13-4d71-92a4-a4164115fe56`，5 次请求，1,163 输入与 379 输出 tokens；额外断言显式 memory_read 的审计回执，避免把默认索引注入误当工具读取。

构建、测试和真实 smoke 的最终结果以本项目 PROGRESS.md 的最新条目为准。

2026-11-13 新增官方原生 Desktop 0.2.2-rc.2 与 Bot 入口验证，见 [HARNESS_QA.md](HARNESS_QA.md)。相同内核的原生预设、公司工具、私有记忆、报告、计量和跨入口排队已实际跑通；品牌发行与统一更新尚未完成。

## 当前实现与原规格的差异

| 原设计 | 本地开发版 |
| --- | --- |
| PostgreSQL 17.11 与 Compose runner | 本机没有 Docker，验证使用项目专用原生 PostgreSQL 18.4；尚未证明容器或 17.11 的兼容性 |
| 隔离 runner | 独立目录、进程、清理后的环境、宿主工具与模型边界；没有 OS 级沙箱，只接公司审查插件 |
| SSO 身份 provider | 后台管理员分配、一次性员工激活与可撤销设备令牌，摘要入库，Windows 长期身份 DPAPI 保护；SSO 尚未接入 |
| 一次任务最多 300 秒，2,048 输出 tokens | 运行凭证 180 秒，SDK请求120秒，单模型网络请求60秒；输出上限1,024，作为初次验证的较小配置 |
| 完整断点续办 | 队列持久化；中断结果进入待核对，不恢复原会话或外部过程 |
| 共享知识发布、CloudEvents 路由、完整市场 | 尚未实现。当前市场内核包含包校验、注册、版本绑定、启停、定向发布和回滚 |
| 发布新版本同时保留活动旧版本运行 | 当前必须先排空目标岗位的活动执行；允许多个已安装版本并存 |
| 金额预算与精确费率结算 | 原子 token 预留与实测/上报标记；费率未配置，不把缺失金额当零 |
| 任意既有系统自动接入 | 必须完成一次 JSON-RPC/RuntimeAdapter 适配；公司 AI 销售、钉钉和云系统尚未接入 |

未实现的方法应明确拒绝，不能通过增加示例 JSON 宣称完成。后续生产接入以这份差异表和行为测试为起点。
